SIT Price Index

GPU-hours now have reference prices. Finished AI work does not. The SIT Index prices a constant amount of capability, whichever lab sells it, and links that price to the GPU-hours needed to produce it. That gives a common unit for buying agent work and a way to measure who earns the margin between hardware and output.

      For operators and lenders

      The crunch spread: who earns the GPU-hour

      Revenue per GPU-hour (token price × tokens produced) minus GPU rent. Positive means renting GPUs to sell tokens pays. The other leg, owner margin, is rent minus the cost of owning the GPU.

      GPU prices higher and token prices lower means the crunch is compressing.Don Wilson, DRW. Gavin Baker replied that the spread is (token price × token volume) − rent, and Wilson agreed. This section uses Baker's form.
      Owner's costOwner margin Producer marginProducer loss

      Four lanes: each tier sold at its index price and at its cheapest-to-deliver price. The cheapest price is where competition sets the floor, so it is the lane that shows whether the squeeze is real.

      The data behind the spread

      Throughput index: tokens per GPU-hour

      The conversion rate between GPU markets and token markets, like a heat rate in power. It depends on the model, the GPU and how fast each user is served, so a SIT unit has to name a speed class.

      Speed class: tokens per second each user sees
      Kimi K3 on B200Kimi K3 on GB200 NVL72● selected speed class

      Serving each user faster means smaller batches and fewer tokens per GPU: Kimi K3 on a B200 produces about 83% less at 150 tokens/s per user than at 30. Fast and slow tokens are different goods, like peak and off-peak power.

      All measured points, with cost per million tokens

      SemiAnalysis InferenceX, late October 2026. Agentic-coding traces for Kimi K3 and MiniMax M3; the older 8K-in/1K-out test for gpt-oss-120b. Counts input and output tokens together. Owner cost is SemiAnalysis's hyperscaler cost of ownership per GPU-hour. Kimi K3 stands in for the frontier because closed labs don't publish throughput.

      For speculators, and the proposal

      The SIT unit

      One unit, two settlement routes. Builders take delivery as tokens; traders settle in cash against the same daily fixing. Because both use one number, arbitrage keeps them aligned, as in power markets.

      Method and checks

      1. Capability bar. Xing's SIT anchors to GPT-4-Turbo (Jan 2024), which every model now clears. This sample uses Artificial Analysis Intelligence Index v5: SITB anchored at 30, SITF at 55.
      2. Price per SIT. Blended list price × (anchor ÷ model score)α; α = 1 is the paper's rule.
      3. Weights. OpenRouter request share by lab, each lab capped at 30%. Updated by hand monthly.
      4. Prices. OpenRouter list prices, refreshed every morning at 06:00 UTC.
      5. Throughput. SemiAnalysis InferenceX at the chosen speed class, interpolated between measured points.
      6. Comparisons. Ornn and Silicon Data values are entered by hand from their public pages and stored with each fixing, so the comparison builds up over time.
      7. Crunch. List prices and on-demand rents, so it describes the marginal renter, not a large operator with owned hardware and negotiated prices.

      Cross-check against Gavin Baker

      P_SIT = P_blended × (S_anchor / S_model)^α Index = Σ w · P_SIT (w_lab ≤ cap) HeatRate = tok/s per GPU × 3600 / 1e6 Revenue = P × HeatRate × utilisation ($/GPU-hr) Crunch = Revenue − Rent Owner = Rent − Capex/(life·8760·occ) − Opex
